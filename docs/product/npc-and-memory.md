# NPC 与社区记忆

## 人物规模与关系

完整首个年龄阶段建议从12—16名常驻人物起步，其中6—8名重点人物承担较长故事、开放对话和关系发展。数字是制作起点，需根据试玩和内容产能调整。当前 Demo 仅有小雨、阿柏、阿乐、林老师与小橘。

每个重点人物需要稳定性格、当前目标、日程、活动地点、未解决的事，以及与其他人的具体联系。店主的孩子、活动组织者、擅长修理的邻居等身份可以把同一事件连接到多个场景。

## 多 Agent 职责

角色 Agent 理解交流、保持身份并提出行动；社区调度管理日程和事件机会；规则系统检查条件、执行结果和保存世界事实。例行移动使用规则，交谈、重要变化、约定到期和小组决策再调用 AI。

社区人物数量与同时调用模型的数量分别管理。多个人物可以共用模型服务，分别读取自己的身份与记忆。多人交流需要参与者、轮次和结束条件。

## 记忆分层

| 类型 | 例子 | 写入与使用 |
| --- | --- | --- |
| 世界事实 | 物品已送到、招牌已完成 | 由规则系统确认，决定任务与奖励 |
| 共同经历 | 一起找小狗、一起做招牌 | 从事件结果写入，影响后续关系 |
| 偏好与约定 | 喜欢画画、答应下次参加 | 记录来源与有效期，可更改或删除 |
| 角色认知 | 听玩家说已经送到 | 作为该角色听到的说法，与核实事实区分 |
| 学习证据 | 某项表达是否依赖提示 | 单独记录，服务难度和复习安排 |

NPC 只读取自己实际知道的信息；消息传播需要依据。年龄阶段切换时保留重要经历并更新人物状态，直接进入较大年龄的玩家使用相应开场背景。

## 生成回答与行动

建议流程：读取世界和玩家状态 → 检索相关且有权读取的记忆 → 生成回答和候选行动 → 检查语言、适龄性及行动条件 → 执行合法变化 → 保存结果。

生成文字不能直接写奖励或制造未支持的新地点。先支持灵活表达与已有事件中的选择，再评估如何从可执行环节组合新事件。保留超时、失败和不理解时的已审核回应。

## 当前实现

Demo 的分支、关键词和本地存档提供有限记忆：材料是否收集、是否完成招牌、选择了什么设计。完成后人物有新回应。它没有实时语言模型、独立后台 Agent、跨设备记忆或长期自主规划。
